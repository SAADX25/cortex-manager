# Cortex Manager PRO v3 — إعادة بناء سيرفر Discord بالكامل

**هذه النسخة مخصصة لسيرفرك Real Friends، وتعمل من GitHub Actions عند الطلب.** تنشئ **7 تصنيفات، 31 غرفة، 13 رتبة ملوّنة**. بها مناطق خاصة للإدارة وVIP، وقوانين ورسائل ترحيب، وصلاحيات مدروسة حسب قدرة البوت.

## ⚠️ تحذير قبل الحذف

وضع `rebuild` يحذف **نهائياً** كل الرومات القديمة التي لم تكن من التصميم الجديد، ويزيل كل الرتب القديمة التي يستطيع البوت حذفها والتي لا يستخدمها البوت بنفسه. **رسائل هذه الرومات والمرفقات وتاريخ المحادثة لن تُستعاد.** النسخة الاحتياطية المرفوعة من GitHub تتضمن **هيكل الغرف وإعدادات الرتب فقط**، ولا تتضمن الرسائل أو ملفاتها أو توزيع الرتب على الأعضاء. تجنب استخدامه على سيرفر عام دون إخبار الأعضاء وأخذ نسخة مما يهمك يدوياً.

هذا المشروع لا ينشئ سيرفر Discord منفصلاً: يعيد ترتيب **السيرفر الحالي** الذي تضع رقمه في `DISCORD_GUILD_ID`.

## التجهيز في GitHub (استمر بنفس مستودع cortex-manager)

1. افتح `Settings → Secrets and variables → Actions` وتأكد أن لديك:
   - في **Secrets**: `DISCORD_BOT_TOKEN` (قيمة التوكن الحقيقية، لا ترسلها لأحد).
   - في **Variables**: `DISCORD_GUILD_ID` (Server ID، رقم السيرفر فقط).
2. نزّل ZIP وفك ضغطه على الكمبيوتر، ثم ارفع **محتويات** المجلد إلى جذر مستودع `cortex-manager` باستخدام `Code → Add file → Upload files`، بما فيها مجلد `.github`. لا ترفع ملف ZIP نفسه.
3. ملف التشغيل الموجود في `.github/workflows/discord-setup.yml` سيستبدل إصدار Cortex Manager السابق ذي الاسم نفسه. ملفات الإصدارات القديمة مثل `index.mjs` يمكن حذفها من المستودع للتنظيف؛ لن يحتاجها هذا الإصدار.
4. افتح `Actions → Cortex Manager PRO - Full Server Rebuild → Run workflow`.
5. اختر `preview` أولاً واضغط Run workflow. افتح التشغيل ثم الـJob، وستجد خطة بأسماء الرومات والرتب **المرشحة للحذف** وأسماء الجديدة، إضافة إلى الصلاحيات الناقصة.
6. احتفظ بنسخة من أي محادثات أو ملفات تهمك من الرومات القديمة يدوياً. ستكون نسخة `cortex-before-...` من هيكل السيرفر متوفرة في **Artifacts** داخل صفحة الـRun؛ **ليست نسخة من الرسائل**.
7. بعد المراجعة، إن كنت تريد الحذف النهائي، اضغط `Run workflow` مجدداً واختر `rebuild` ثم أدخل:
   - `confirm_guild_id` = **نفس رقم السيرفر تماماً** الموجود في `DISCORD_GUILD_ID`.
   - `confirm_delete` = `DELETE_ALL_OLD_CHANNELS_AND_ROLES`
8. انتظر انتهاء التشغيل وافتح Summary/Logs وتقارير Artifacts. إن ظهرت علامة فشل، راجع الرسالة؛ قد تكون هناك رتبة محمية أو صلاحية تمنع الإكمال.

**لا تحتاج إلى أي استضافة مستمرة:** يستخدم Discord REST API من GitHub Actions، لذا قد يبقى البوت Offline حتى بعد نجاح المهمة.

**مهم جداً بشأن الصلاحيات:** البوت لا يستطيع منح صلاحية هو نفسه لا يملكها. إذا كان `Cortex Manager` حاصل فقط على `Manage Channels` و`Manage Roles` و`View Channels` و`Send Messages`، فسيُنشئ الرتب **بالصلاحيات الممكنة فقط** ويسجّل في الـPreview كل صلاحية متقدمة ناقصة. وكذلك سيتم حذف صلاحيات الـOverwrites غير المدعومة من إعدادات الرومات، وقد لا يكتمل تقييد الرتبة Muted أو سماح الصوت حتى تمنحه صلاحيات الصوت والتفاعلات المناسبة. للحصول على إدارة احترافية كاملة، أضف له من `Discord Developer Portal → Installation → Guild Install → Permissions` ما تحتاجه فعلاً، مثل `Manage Messages`, `Kick Members`, `Ban Members`, `Moderate Members`, `Manage Server`, `View Audit Log`, `Manage Nicknames`, `Manage Events`, `Move Members`, `Manage Threads`, `Connect`, `Speak`, `Add Reactions`, `Create Public Threads`, `Create Private Threads`, `Send Messages in Threads`، ثم احفظ التغيير وأعد تخويل/تثبيت البوت إذا تطلب Discord تحديث صلاحياته. **لا يحتاج Administrator.** لا تعطي الأدوار العالية لأي شخص غير موثوق.

المالك الفعلي يُمنَح رتبة Founder الشكلية فقط تلقائياً. **لا تُوزع رتب Co Owner وAdmin وModerator تلقائياً** منعاً لمنح سلطات لأشخاص غير مقصودين. وزّعها بنفسك بعد التنفيذ.

## الحماية والقيود

- `preview` لا يغير شيئاً.
- `rebuild` يحتاج **تأكيدين منفصلين**: رقم السيرفر الصحيح + عبارة الحذف الدقيقة.
- قبل أي تعديل، يتم **رفع نسخة هيكل** إلى GitHub Actions كـArtifact. المستودع يُفضّل أن يكون Private.
- ينشئ الرتب والغرف الجديدة أولاً، ثم يحذف القديم.
- لا يحذف `@everyone` ولا رتب تكاملات Discord أو أي دور يحمله البوت نفسه، ولا يستطيع تجاوز التسلسل الهرمي للأدوار.
- في بعض السيرفرات المجتمعية لا يمكن حذف روم القوانين أو تحديثات المجتمع قبل تغيير ربطه في `Server Settings`; التنفيذ يتوقف لتفادي نتائج غير مكتملة.
- إذا كان بعض الرتب أعلى من رتبة البوت، يتوقف قبل تعديل السيرفر. حرّك رتبة Cortex Manager فوق الرتب المطلوب استبدالها، **لكن أبقِ رتبة مالك السيرفر الفعلية محمية إذا كنت لا تريد حذفها**.
- قد تعيق صلاحيات روم خاص عملية الحذف. وضع المعاينة يحاول كشف ذلك.
- حذف الرتب القديمة يسحبها من الأعضاء الحاليين. راجع من سيحتاج رتب جديدة بعد إعادة البناء.
- بعض القنوات المنشأة بواسطة تكاملات أخرى قد تتطلب إعادة ربط تطبيقاتها بعد الاستبدال.
- لا يستطيع البوت حذف سيرفر Discord نفسه ولا إنشاء سيرفر جديد من الصفر بهذا المشروع.

## تخصيص التصميم

عدّل ملف `src/design.mjs`: يحتوي على أسماء الرتب وألوانها وصلاحياتها وأسماء الأقسام والرومات ورسائل الترحيب. بعد أي تعديل شغّل `preview` ثم `rebuild` **فقط إذا أردت فعلاً إعادة البناء**. عند تشغيله مرة ثانية، يتم الحفاظ على العناصر التي تتطابق مع التصميم الجديد بالاسم والمكان، وحذف القديمة غير المطابقة.

## الأخطاء الشائعة

- **401:** Token غير صالح؛ حدّث Secret بعد Reset Token.
- **403:** صلاحيات البوت ناقصة أو مرتبته غير كافية أو هناك Channel Overwrite.
- **404:** Server ID غير صحيح أو البوت غير موجود فيه.
- **Blocked: protected channels:** غيّر إعدادات Community للقنوات المحمية أولاً.
- **Blocked: roles not below bot:** حرك رتبة البوت أعلى الرتب التي تريد حذفها.
- **ظهور البوت Offline:** طبيعي، لأنه سكربت عند الطلب وليس Bot Gateway دائم.
- **علامة خضراء بعد preview:** تعني أن المعاينة نجحت، وليس أن السيرفر تغير.

تستخدم هذه النسخة Node.js 22 وDiscord API v10 مباشرة، بدون حزم أو توابع خارجية، مع اختبار `node --test` قبل التشغيل.
